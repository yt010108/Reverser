# 핵심 기법: SUBLEQ/VM 이미지의 dead-data 문자열 조기 확인

- 대상 유형: 커스텀 VM(예: SUBLEQ) 바이트코드 이미지가 통째로 데이터로 주어지는 rev 문제.
- 교훈: 복잡한 변환(격자 unscrambling, 순열 복원)에 들어가기 전에, 코드 영역 뒤 상수 영역을
  워드 단위로 덤프한 뒤 **양수/음수 두 극성으로 즉시 ASCII 디코딩**할 것. 플래그 문자열이
  실행 경로에서 도달 불가능한 dead data로 심겨 있는 경우가 흔하다(음수화 저장 포함).
- 절차:
  1. 16-bit LE 부호 해석으로 전체 워드 덤프 (2의 보수).
  2. 값이 -128..-1 또는 32..126 범위에 밀집한 연속 구간을 문자열 후보로 마킹.
  3. `chr(-v)` / `chr(v)` 양쪽으로 디코딩해 사람이 읽히는 쪽 채택.
  4. 코드 영역 피연산자에 해당 주소 참조가 없으면 dead data 확정 — 동적 실행 불필요.
- 효과: 이번 사례에서 격자 복호화 시도(~20분)를 생략 가능했을 시도.
