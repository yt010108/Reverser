# 기법: 커스텀 VM 바이트코드 경계 부트스트래핑 + 대시 정합성 소거 (brunnerctf-2026-lockdown-mode)

## 적용 문제
LEGO EV3풍 커스텀 VM 바이트코드(recovered.rbf, 1087B) — 실행 환경(워커) 장애 시에도 순수 정적 분석으로 구조 복원이 어디까지 가능한지 검증된 사례.

## 핵심 1: 앵커 기반 경계 부트스트래핑
실행/디버거 없이 명령 경계를 확정하는 순서:
1. **인라인 문자열**: `80 <문자열> 00` 피연산자는 길이 자명 → 디스플레이 호출 전체(`84 05 01 x y <str>`, `84 13 00 00 00` 클리어, `84 00` 업데이트)가 곧 경계.
2. **점프 교차검증**: rel16 점프(`82 imm16`, LE signed, target = jump_addr+3+imm)의 착지점이 반드시 경계. 파일 말미의 오류 처리 점프(0x43B→0x18B)가 파서 문법 전체를 검증함.
3. **반복 유닛**: 테이블 빌드 코드는 동일 유닛 반복(`cc <val> <slot> c1 34` / `... c2 b1 00`) — 유닛 길이로 op 아리티 확정(CC=2슬롯, C1=1슬롯, C2=2슬롯).
4. **버튼 체인 역방향 정렬**: `83 01 <btn> 42 42 42` + `82 imm16` 연쇄에서 모든 forward 점프가 경계에 떨어지도록 오프셋 정렬 → 핸들러 주소표 완성. 마지막 버튼은 EOF halt(0x43E)로, 폴스루는 메인 헤드로 귀결되면 정렬 성공.

## 핵심 2: 대시 정합성 논법 — 상태비저장 선형 모델 일괄 소거
GUID 형식 플래그('-'가 p∈{8,13,18,23}에 고정)에서 차분 재사용:
- Z256: v=A·g(c)+B·p+C 가정 시 dash 위치들이 요구하는 B가 서로 다름(5B≡130 ∧ 5B≡30 mod 256 모순, gcd(5,256)=1). A·c·p 결합형도 동일 구조로 사망.
- GF(2): 8⊕13 = 18⊕23 = **5**라서 clmul 아핈(M_B·5가 두 값을 동시에 가져야 함)도 즉시 모순.
- LCG 키스트림(가감/XOR)은 dash 4개로 3원2식 연립이 불능임을 손계산 가능.
- 교훈: **실행 전에 이 테스트부터 수행** — 그렇지 않으면 소거된 계열의 브루트포스에 수회 실행 낭비(실제로 4회 발생).

## 잔존 판별 단서
코드 내 상수(0x7FFFFFFF/0xFFFF 마스크, const16 1337, 0x78/0x64)와 이중 36회 루프 구조는 상태형 롤링해시(h=h·A+c, 폭 16/32비트) 가설을 지지 — 다음 우선 타깃.

## 재사용 포인트
- 문법 불명 VM: 문자열/점프/반복유닛 3종 앵커만으로 아리티 복원 가능.
- 플래그에 구조적 고정 문자(GUID 대시 등)가 있으면 동일문자·다른위치 비교로 선형 모델 계열을 실행 없이 소거.
