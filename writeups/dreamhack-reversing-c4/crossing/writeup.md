## 인코더 분석 (radare2, Ghidra 없이 pdf로 해결)
- `main` (0x1664): 파일 크기 S에 대해 n² ≥ 100·S인 최소 n 계산 → calloc(n²). 원본 S=18447 → n=1359, n²=1,846,881 = 제공 파일 크기와 정확히 일치. 실패 시 memset 후 전체 재시도, 성공 시 그리드를 row-major로 fwrite.
- `fcn.1591` (0x1591): 파일을 1바이트씩 읽어 i=2k(상위 니블), i=2k+1(하위 니블) 슬롯으로 `fcn.1364(n, buf, i, nibble)` 호출.
- `fcn.1364` (0x1364): 패턴 구성
  - `[0xFF][ (i+1)의 base-253 자릿수, 각 자릿수+2, LSB 먼저 ][0xFF][0x01 × (니블+1)]`
  - 자릿수+2 인코딩 덕분에 패턴 바이트는 0x00/0x01/0xFF와 절대 충돌 없음 (마커/원스와 구분 가능).
  - getrandom 기반 난수(`fcn.12e9`)로 시작 위치/방향(가로=연속, 세로=stride n)을 뽑아, 기존 셀과 일치하거나 0인 경우에만 배치. 100회 시도 후 실패 시 0 반환.
- 격자의 FF 셀은 비교 시 sign-extended(-1) vs zero-extended(255) 불일치로 절대 겹칠 수 없음 → 모든 패턴 시작점이 유일하게 식별됨.

## 디코더 (worker: core, python3)
1. 그리드 전 스캔(가로/세로): `0xFF` → 자릿수(2..254) 1개 이상 → `0xFF` → 0x01 최대 런(1..16) 파싱 → (idx, v=런길이-1) 후보 수집.
2. 결과: 36,913 후보, idx 0..36,893 빠짐없이 존재(2·18447=36,894 니블), 중복 19건.
   - 중복 원인: 밀집 영역에서 `[다른 패턴의 FF][우연한 자릿수][FF][원스]`로 엮인(stitched) 가짜 파싱. 1자릿수 파싱은 idx<253 범위에서 반드시 기존 idx와 충돌 → 중복 19건 대부분이 idx<253.
3. 중복 판별: 시작 셀이 수직 방향으로 `[자릿수][0x01]`(=다른 패턴의 종결자) 문양이면 가짜로 제거. 잔여 모호 슬롯은 양자화 테이블 내부(가독성 무관) 또는 엔트로피 1바이트.
4. 재조립: byte[j] = nibble(2j)<<4 | nibble(2j+1), 길이 18,447. `FFD8` 시작, `FFD9` 종료, JFIF/DQT/SOF0(320×204) 헤더 정상 복원 확인.
5. idx 14999(엔트로피 영역, 바이트 7499) 후보 교체로 깨진 글리프 1개 복원 → 이미지 텍스트 판독 완료.
