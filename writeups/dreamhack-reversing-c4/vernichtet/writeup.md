# Vernichtet (Dreamhack Reversing C4) — write-up

## 개요
- 대상: `main` (ELF x86-64 PIE, stripped, 15160 bytes)
- 동작: `./main <answer file>` — 정답 파일을 검증해서 "Correct!"를 출력하고,
  `bash -c "echo [FLAG REDACTED]')}"` 를 실행해 플래그 출력.
- 즉 **플래그 = [FLAG REDACTED]**.

## 분석
`main`:
1. 파일 크기가 정확히 `0xe1`(225) 바이트여야 함.
2. 검증 함수 #1 (`0x1269`): `.data:0x4020`의 3바이트 엔트리 225개
   `(col, row, expected)` — expected가 0이 아닌 셀은 `buf[row*15+col] == expected` 여야 함.
   → 15x15 격자에 **150개의 고정 힌트 칸**.
3. 검증 함수 #2 (`0x138e`):
   - 값이 1인 칸에서 시작해, n번 반복: 현재 칸의 **8방향 이웃** 중 값이 n+1인 칸으로 이동.
   - 마지막까지 못 찾으면 실패.
   → **Hidato(숫자 스네이크)** 퍼즐: 각 칸이 1..225를 한 번씩 가지고,
     연속된 숫자의 칸이 킹 이동으로 인접해야 함.

## 풀이
1. `.data`(vaddr 0x4000 → file off 0x3000)에서 225개 triple을 읽어 힌트 격자 복원.
2. Python 백트래킹 솔버 작성:
   - 값을 1→225 순서대로 배치, 다음 후보는 현재 칸의 미사용 8방향 이웃.
   - 가지치기: (a) 다음 힌트 위치까지 Chebyshev 거리 ≤ 남은 스텝 수,
     (b) 미사용 칸들이 다음 힌트 칸을 포함해 하나의 연결 영역이어야 함(BFS).
   - 약 269만 노드, ~213초에 유일해 도출.
3. 해답 15x15 격자를 raw bytes(각 칸 = 숫자 1바이트)로 저장한 것이 정답 파일.
4. 워커에서 실제 바이너리 실행으로 검증: `Correct!` + 플래그 출력 확인.

## 참고
- gcc가 없는 core 프로필이라 솔버는 Python으로 작성 (충분한 속도).
- reverser_exec는 매 실행마다 새 컨테이너라 /tmp 파일이 유지되지 않음 → 추출+솔브를 한 명령으로 합쳐야 했음.
